=== WHY THIS THIRD SET EXISTS AND WHAT IT ISOLATES ===

Three builds were taken, not two, because the migration changes two things at
once on this track and a single comparison cannot separate them:

  build A  base-commit tree, yarn 1.22.22, Node  8.17.2 era runtime (v8.17.0)
           -> artifact-digests-node8.txt, and the five digests recorded in
              ../baseline/artifacts/
  build B  base-commit tree, yarn 1.22.22, Node 20.20.2
           -> THIS FILE
  build C  migrated tree, npm 10.8.2 from the committed lockfile, Node 20.20.2
           -> artifact-digests-node20.txt, and the five digests recorded in
              ../migrated/artifacts/

B against C holds the RUNTIME constant and varies only the package manager, the
lockfile and the dependency-specification form.  Every one of the five compared
artifacts, and the source map, is byte-identical between them -- so the manifest
rewrite from 76 owner/repo#<semver-range> specifications to 76 exact commit SHAs,
the replacement of the superseded lockfile with package-lock.json at
lockfileVersion 3, and the change of installer resolved to the same dependency
graph and drove the pipeline to the same bytes.  That is the strongest statement
available about the change this migration actually makes to the frontend, and it
is unambiguous.

A against C is the comparison the review asked for, and it varies BOTH the
runtime and the package manager.  Three of the five artifacts are byte-identical;
two differ, both of them minifier output, and comparison.txt in this directory
carries the full analysis.  Read against B, the attribution is settled rather
than argued: since B and C agree byte for byte, the two differences between A and
C cannot be caused by the package manager, the lockfile or the specification
form, because those are exactly what B and C differ in.  The only variable left
between A and B is the Node runtime the minifier ran on.

The captures under ../baseline/ and ../migrated/ hold A and C, because A against
C is what the migration criteria call for.  B is preserved here rather than in a
capture directory of its own so that the attribution above can be checked, and
its digests are the ones ../baseline/artifacts/ carried before that capture was
re-taken on the historical runtime.
