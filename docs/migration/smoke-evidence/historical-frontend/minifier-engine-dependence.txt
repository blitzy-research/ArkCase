  READING THIS.  The style minifier restructures selectors that share a body, and
  that pass sorts with comparators returning a boolean rather than a signed number.
  Such a comparator can never report "less than", so the permutation the sort
  produces is decided by the engine, not by the comparator.  The two runtimes
  disagree on the 24-item demonstration above — one returns a scrambled order and
  the other the order it was given — which is the newer engine having replaced its
  sort algorithm.  The comparators are at, relative to the minifier package:
      lib/selectors/restructure.js  naturalSorter  and  fitSorter
      lib/selectors/clean-up.js     the two selector sorts
  That is a latent defect in a third-party package, not a migration change, and it
  is registered as pre-existing rather than repaired: the package installs and runs
  on the target runtime, and the migration only permits replacing a build package
  that cannot.

WHAT THIS ESTABLISHES
  The tool trees are identical and the inputs are identical, so no dependency,
  tool or input drift is present to remove.  The one variable left standing is
  the runtime, and the runtime move is the change the migration exists to make.
  Byte identity on the two affected artifacts is therefore reachable only by
  running the build on the superseded runtime, which the migration forbids in
  the same breath as it requires the move.  The two requirements cannot both be
  satisfied, and that is reported as an unresolved divergence rather than
  settled quietly in favour of whichever one is easier to show as met.
