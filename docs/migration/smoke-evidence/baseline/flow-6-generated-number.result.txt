  the default optimizer path.  It reproduced that error against
  a bean compiled for the older release -- that is, at the JDK 8 target --
  which places the defect in the code the library itself generates rather
  than in the classes it reads.  No way of compiling the application

  edit reaches the classpath at all.  Every library version in this reactor
  is declared exactly once as a root-aggregator property and consumed by
  reference, and that is what lets a 145-module runtime migration be
  expressed as a property edit rather than as 145 of them.
