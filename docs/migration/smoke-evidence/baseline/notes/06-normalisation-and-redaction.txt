what the literal stage substitutes, BY NAME and never by value:
  the configured administrator password  -> the redaction token
  the resolved capture root              -> <CAPTURE-DIR>
  the capture output directory           -> <CAPTURE-DIR>
  the absolute repository root           -> <REPO-ROOT>
  the running account home directory     -> <HOME>
  the scratch directory for this run     -> <TMPDIR>
  The four path substitutions are boundary-aware: a longer name that
  merely begins with one of these paths is left verbatim, so a file called
  <root>-backup is not rewritten as if it were inside <root>.

live self-test of the pipeline.  Every probe below is SYNTHETIC — no probe
value here is a real credential, a real identifier or a real response.
Each is pushed through the live pipeline and both sides are recorded, so
this ledger states what the pipeline DID rather than what it should do.

read the in: column knowing that it is DOUBLE-SANITISED.  The assertion
itself runs on the raw probe value, which is how a rule can be observed to
fire at all; but this whole block is then written through the same pipeline
as every other capture byte, so a credential-shaped probe appears redacted
in its own input column too.  That is deliberate defence in depth rather
than a display fault: the file is a committed artefact, and no code path
that writes into it gets to opt out of the sanitiser — not even the one
testing the sanitiser.  The rule is still demonstrably firing, because the
out: column shows the whole matched span replaced rather than just the
probe value substituted.
