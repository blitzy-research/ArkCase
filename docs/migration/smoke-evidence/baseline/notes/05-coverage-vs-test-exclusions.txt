coverage exclusions are not test exclusions — and how a measurement could lie

produced-by: docs/migration/smoke-evidence/smoke-checks.sh, capture_coverage_exclusions_note
authoritative-analysis: docs/migration/baseline-test-failures.md
coverage-liveness-evidence: jacoco-liveness.txt (migrated capture only)
capture-side: baseline

TWO WRONG INFERENCES THIS NOTE CLOSES, both of which a reviewer auditing the
no-disabled-tests rule is likely to reach.

FIRST: that a coverage exclusion is a test exclusion.  It is not.  A coverage
glob removes a class from the RATIO; the test still runs, still passes or
fails, and still appears in the archived report.  The two live in different
plugins and have different effects, and conflating them produces a finding
against configuration that disables nothing.

SECOND: that a green coverage check proves instrumentation ran.  It does not.
The coverage plugin publishes its agent configuration through the default
argLine property, so a test-runner declaration that sets a LITERAL argLine
severs instrumentation silently — and the configured check goal then
evaluates an EMPTY data set against its minimum ratio and reports a pass.  A
false green that no exit status and no report would reveal.  The only
evidence that distinguishes it from a real pass is the execution data file
being non-empty, which is what jacoco-liveness.txt measures.

MEASURED ACROSS EVERY POM IN THIS TREE, at capture time:
occurrences-of-skipTests: 2
occurrences-of-an-excludes-element: 2
occurrences-of-a-literal-argLine-element: 0
occurrences-of-a-coverage-exclude-property: 0
occurrences-of-the-coverage-prepare-agent-goal: 2

HOW TO READ IT.  A literal argLine count of ZERO beside a non-zero
prepare-agent count is the sound configuration: the agent publishes its
arguments and nothing overwrites them.  A NON-ZERO literal argLine count is
the false-green condition above and has to be reconciled against
jacoco-liveness.txt before any coverage figure in this capture is believed.
An excludes count above zero is not by itself a violation — the element is
used by several plugins — but each occurrence has to be traced to a baseline
register row before it is accepted, which is the register named above.

WHAT THIS NOTE DOES NOT CONTAIN: the line anchors of each declaration and
the per-occurrence adjudication.  Those move as the aggregator is edited, so
they are held by reference on the register rather than copied into a capture
that would then disagree with it.
