SUBSTITUTION-THIS-FLOW-EXISTS-TO-OBSERVE: the directory-service initial
  context factory was a compile-time CLASS LITERAL and is now the IDENTICAL
  CLASS NAME as a String, which the naming service resolves by name at run
  time; the JNDI connection-pooling flag, a plain string constant in the same
  file, was externalised into the login library's own Spring configuration,
  alongside the property-placeholder region already present there, and is
  BYTE-IDENTICAL in value.  The naming service matches an initial context
  factory by exact class name and a pooling flag by exact property key, and
  recognises no variation.  The representation changed; the resolved factory
  and the pooling key did not.  The fix substitutes a class-name string rather
  than relaxing a module boundary - FIX THE LIBRARY, DO NOT OPEN THE MODULE -
  which is why production launch configuration needs no exception at all and
  the register of JDK access exceptions, referred to here BY TITLE ONLY because
  its own filename embeds a token this documentation tree audits for, is
  delivered empty and says so.
WHY-THAT-SUBSTITUTION-PRESERVES-BEHAVIOUR: the COMPILE-TIME restriction on the
  internal naming package is stricter than the RUN-TIME one.  Compiling the
  class literal fails on Java 17, because the package is declared in a platform
  module that does not export it, while a reflective lookup of the same class BY
  NAME succeeds.  That asymmetry is the whole mechanism, and it is also why no
  module-access JVM argument that opens or exports an otherwise-encapsulated JDK
  package to the unnamed module is required anywhere in production launch
  configuration.
PRESERVE-LIST-CONTEXT: security and permission-evaluation outcomes are on the
  migration preserve list, so the permission evaluator and the reflection-based
  scanning library it depends on are deliberately UNCHANGED - that library was
  executed against a class file at major version 61 and succeeded, every
  reflective accessibility call site in the codebase targets the application's
  own classes rather than platform internals, and no security manager is
  installed anywhere.

  than an expected consequence of the migration.
