WHAT THIS FILE IS
  The provenance narrative that 1 report in this archive carried INSIDE the
  report file, as an XML comment between the declaration and the root element.
  Every block is reproduced below verbatim, under the path of the report it
  was taken from, and nothing was summarised away.

WHY IT WAS MOVED
  The archive contract is that a report payload is what the runner wrote, apart
  from the two transformations install-surefire-evidence.sh performs and counts:
  absolute machine paths become placeholders, and the system property dump is
  reduced to an explicit literal allowlist.  A hand-authored comment is neither
  of those, and the register that documents this archive states in terms that
  each report carries its provenance NATIVELY rather than in a comment ahead of
  its root element, having replaced an earlier revision that prepended one to
  every report.  These 1 file still carried theirs, so the register was
  falsified by its own archive.
  Moving the narrative here rather than deleting it keeps both properties: the
  payloads are again byte-identical to the installer output, and no reasoning is
  lost.  The reports were verified byte-for-byte against the installer output
  after the comments were removed, so the removal took nothing else with it.

WHY THE NARRATIVE MATTERED IN THE FIRST PLACE
  Each block was addressed to a reviewer checking that the rule against
  disabling failing tests is verifiable rather than merely asserted.  That
  question is answered by the report itself - by the testcase elements it
  carries, the outcome elements attached to them and the native
  java.runtime.version in its retained properties - which is precisely why the
  narrative belongs beside the reports and not inside them.

WHERE THIS FILE LIVES, AND WHY NOT IN A MODULE DIRECTORY
  Each module directory in this archive admits report XML and nothing else: no
  index, no summary, no notes file.  This file therefore sits under notes/
  beside the module directories, in the same position as run-provenance.txt and
  sha256-manifest.txt, and it is covered by that manifest like every other file
  here.
