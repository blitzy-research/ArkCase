  7b. THE EASYMOCK EXCEPTION, AND WHY IT MAKES THIS THE MODULE'S PUREST RUNTIME PROBE. Nine of this
      module's ten unit test classes extend the EasyMock support base class. This class is the
      tenth, and it is the only one that does not: verified by direct count, it has zero references
      to that library, no superclass and no runner annotation.
      The EasyMock floor advance has the widest build file footprint of any change in the migration.
      The installed release and the intermediate one fail identically on the target runtime with an

      later release succeeds. The module declares the library version-less at base commit lines 230

      the picture, this report isolates the runtime and the templating stack alone. If the other
      nine diverge on the migrated side and this one does not, the divergence points at the mocking
      library advance. If THIS one diverges, the cause lies in the runtime or in the templating
      dependency chain, and not in mocking. The archive therefore carries a built-in diagnostic
