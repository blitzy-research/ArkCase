That asymmetry is the whole mechanism — the field's type changes from a class to the identical class name as a string, and the naming service consumes it identically.  It is also why no module-access argument that opens or exports an otherwise-encapsulated JDK package to the unnamed module is required anywhere in production launch configuration, and why the JDK access exceptions register is delivered empty and says so
