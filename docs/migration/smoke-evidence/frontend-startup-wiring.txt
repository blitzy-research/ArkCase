----- what this does and does not establish -----
ESTABLISHES, by execution:
  * the Windows branch resolves a launchable Node probe.  The suffix that names a batch
    wrapper reaches the path-qualified Grunt CLI and reaches neither bare-name launcher,
    so 'cmd /C node.cmd --version' -- which cmd cannot resolve, and which ran BEFORE the
    install -- is gone.  The Linux and macOS branches resolve exactly what they resolved
    before, which is why the captures taken on Linux remain comparable.
  * the child environment is composed rather than inherited.  A variable exported into
    the parent and needed by no build step does not reach the child.
  * package lifecycle scripts are disabled for the install by the delivered default.
  * the toolchain majors are enforced in both directions: this host's real launchers are
    accepted, and a required major this host cannot satisfy is refused with a diagnostic
    naming it.

DOES NOT ESTABLISH:
  * anything about a real Windows host.  os.name is simulated, so what is verified is the
    COMMAND each branch resolves, not its execution on Windows.  That is the whole of the
    defect that was found and fixed, and it is as far as this can go from Linux.
  * that the residual weaknesses of this seam are mitigated.  They are not: there is no
    execution timeout, the launcher is still resolved by name rather than pinned to an
    absolute path, the file operations still follow symbolic links, and one deletion
    result is still discarded.  All four are base-commit behaviour and all four are
    registered as entry 58 of ../pre-existing-defects.md.
  * that a deployment logs any of this.  The external configuration pins this logger to
    warn, which suppresses the INFO narrative; the failure paths throw, so they are
    visible regardless.
