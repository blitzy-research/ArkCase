WHY THIS FILE IS NOT PART OF THE DOCUMENT ROUND-TRIP EVIDENCE
  The round-trip flow sends its document with an EXPLICIT content type on the
  request, so the application never resolves one and the activation defaults are
  never consulted on either leg.  A successful round trip would look exactly the
  same with the wrong artifact, and the flow cannot run at all where the content
  repository is not provisioned.  Evidence for a behavioural artifact choice
  cannot rest on a flow that does not exercise the behaviour, so the behaviour is
  exercised here instead, directly and without a network.

THE ONE RESOURCE THAT MATTERS, REFERENCE IMPLEMENTATION AGAINST LEGACY 1.1
  as bytes:   581 bytes against 606 bytes — DIFFER
  as mappings: 22 pairs against 22 pairs — 0 differing
  VERDICT: the archives differ only in comments.  Classpath order between
  these two cannot change a resolved media type, because there is no mapping
  on which they disagree.
  This comparison exists to hold one register entry to its evidence.  The
  reasoning first recorded for rejecting the legacy jar was that its copy of this
  resource differs from the reference implementation's.  It does, as bytes.  It
  does not, as mappings, and the mappings are what the map is built from.  The
  rejection is sound on other grounds — an artifact this migration depends on is
  pinned explicitly rather than inherited, and two providers of one package is a
  duplicate-provider classpath — but not on this one, and the register now says so.

WHAT THE DEPLOYED ARCHIVE ACTUALLY SHIPS
  WEB-INF/lib/javax.activation-1.2.0.jar 
  Exactly one activation jar on the deployed classpath is the intended state: a
  second provider for the same package would make resolution order-dependent,
  which is why the reactor excludes the legacy standalone jar from both of the
  dependencies that drag it in.

WHAT THIS FILE ESTABLISHES, AND WHAT IT DOES NOT
  It establishes that the artifact choice is behaviour-bearing and that the
  artifact the deployment ships is the one that carries the resources the call
  reads.  Read the observed captures above rather than this sentence: they are
  the evidence and this is a summary of them.
  It does NOT establish that any application code path ran in a deployed
  container.  It exercises the API the consumers call, on the same runtime, from
  the same artifact the deployment ships; it does not observe the consumers
  themselves.  The class-level assertions for those live in the archived unit
  suite, and observing them end to end needs a mail or capture path that this
  environment does not provide.  Both limits are stated rather than left to be
  inferred from a passing probe.
