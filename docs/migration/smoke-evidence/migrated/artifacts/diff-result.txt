frontend artifact byte-identity comparison - the adjudication
+++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++

WHAT THIS FILE IS
  The comparison record for the frontend track's substantive behavioural
  criterion: the five built artifacts must be byte-identical to the baseline
  build.  It records, per artifact, whether the migrated digest matches its
  baseline twin, and it carries one overall verdict.

  It is not a summary.  It is the verdict.

WHY IT CARRIES SO MUCH WEIGHT
  The frontend tree contains ZERO spec files.  Re-measured for this record
  rather than taken from the plan:

    find acm-standard-applications/arkcase/src/main/webapp/resources \
         -name '*.spec.js' -not -path '*/node_modules/*' | wc -l     ->  0

  A test runner and an assertion library are declared in the manifest, but
  nothing is wired to them.  There is therefore NO automated behavioural test
  for this track at all, which makes artifact byte-identity the strongest
  available behavioural evidence - and this file is where that evidence is
  adjudicated rather than merely reported.

HOW THE COMPARISON WAS MADE
  POSIX text tools only: sha256sum, awk, grep, sed, sort, diff, cmp.  No JSON
  processor, no script runtime, no installed package, no test framework and no
  markup parser was added or used.  Adding a tool to compare two 64-character
  strings would be a dependency change with no compatibility reason, and the
  rule requiring a specific compatibility reason for every dependency change
  forbids it.  The producer that wrote the ten input records is held to the
  same fence: it digests with sha256sum, falling back to shasum -a 256, and
  parses with awk (smoke-checks.sh:L3356-L3359, fence stated at :L210).

  Each field was parsed on the TWO-SPACE separator that the record schema
  defines, not on generic whitespace, so no whitespace-normalising convention
  could collapse the fields.

OVERALL-VERDICT: FAIL - the byte-identity criterion is NOT SATISFIED
+++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++
  The criterion is a pass only when all five rows are MATCH.  Two rows are
  MISMATCH, so it is a fail.  That is stated once, plainly, and it is not
  softened into a caveat, not restated in gentler terms further down, and not
  recovered by widening what "identical" means.  A SKIPPED row would have left
  the criterion UNSATISFIED for a different reason; none occurred.

  WHAT THIS VERDICT DOES NOT SAY.  A fail on this criterion is not the same
  finding as "the migration changed what the application loads", and this file
  will not quietly convert one into the other in either direction.  The two
  differences have been characterised to the byte, their cause isolated by
  positive elimination rather than argued from plausibility, and both are
  registered as accepted, evidenced deviations - in the ambiguity-resolutions
  register at entry 6a and as row 13 of the pre-existing-defects register,
  both under docs/migration/.  A difference that appeared in NEITHER register
  would be an unexplained difference, and that is the condition this file
  exists to make impossible to miss.  Neither of these is unexplained; both
  are nonetheless counted as mismatches here, because the criterion asks about
  bytes and the bytes differ.

WHY BYTE-IDENTITY IS A LEGITIMATE CRITERION AT ALL
+++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++
  Established before it was relied on, because a pipeline with any
  nondeterminism would make the criterion meaningless.  Every anchor below was
  re-derived against the 380-line Gruntfile.js for this record.

  Gruntfile.js:L79-L86   cache busting is CONTENT-HASH based.  The assets glob
                         at :L82 is [ 'assets/dist/**' ] and the rewritten
                         source at :L84 is [ 'home.html' ].  There is no
                         timestamp, no build banner and no date injection
                         anywhere in the task.
  Gruntfile.js:L51       mangle : false - identifier mangling is DISABLED,
                         which removes the principal source of benign
                         inter-build variance and is what makes comparing a
                         minified bundle meaningful at all.
  Gruntfile.js:L131      clean: [ 'assets/dist' ], and clean runs SECOND in
                         the default graph, so the distribution directory is
                         wiped before anything is written to it and a stale
                         artifact cannot masquerade as a match.
  Gruntfile.js:L376      the default graph, unchanged by this migration:
                           loadConfig, clean, ngAnnotate, uglify, concat,
                           cssmin, renderHome, cacheBust,
                           copyToModulesConfigFolder
                         Nine tasks, in that order, so both runs produce the
                         same five artifact names by construction.

  THE PIPELINE IS RETAINED, NOT REPLACED, AND THAT IS A COMPLIANCE DECISION.
  The task runner at ~0.4.5 and its command-line companion at ~0.1.13
  (package.json:L8 and :L9 in the current manifest; :L9 and :L10 at the base
  commit) were verified to install AND execute on the new runtime, so both are
  deliberately left exactly where they are.  The rule requiring the frontend to
  run genuinely on the new runtime constrains OVERREACH just as firmly as it
  forbids pinning to an old runtime: a tool that runs is not touched, and only
  a tool that cannot run is replaced.  This record accordingly makes no
  recommendation to modernize the task graph, and none should be read into it.


THE ONE HONEST CAVEAT - THE SOURCE MAP
+++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++
  Gruntfile.js:L52 sets sourceMap : true, in the same minifier options block
  as the mangle setting at :L51, and that block is what produces
  assets/dist/application.min.js.  A source map EMBEDS THE PATHS OF ITS
  INPUTS.  renderHome additionally writes to a RELATIVE target
  (Gruntfile.js:L177 writing to config.homePage.target, declared as bare
  home.html at config/env/all.js:L22).

  The comparison build must therefore execute from the same relative path as
  the baseline capture, or the map will differ while the JavaScript bundles are
  unaffected.

  WAS THE SAME RELATIVE PATH USED?  NO.  Stated plainly rather than left to
  inference: the migrated side built in-tree under the repository root, and the
  baseline side built in a scratch directory outside the working tree, in a
  different clone, beneath an extra blitzy_adhoc_test_buildA path segment.  The
  two roots differ by construction - the baseline is a build of the base-commit
  tree extracted elsewhere, which is the only way to obtain it at all.

  CONSEQUENCE, AND IT IS NOT HIDDEN.  The source map is EXCLUDED from the byte
  comparison, while ALL FIVE contracted artifacts REMAIN IN SCOPE.  The
  exclusion is visible in three places and was not applied silently: on the
  advisory row above, in notes/determinism-basis.txt and notes/artifact-gate.txt
  one level up, and in comparison.txt beside them.  The map is still digested
  on both sides so that the exclusion can be checked instead of trusted, and
  its digests are printed on the advisory row above for exactly that purpose.

  No sixth digest record was added for the map by this file - the record it
  already has was written by the producer, and this file added nothing to the
  directory but itself.

  A NOTE ON HOW MUCH THE PATH DIFFERENCE EXPLAINS.  It accounts for the map.
  It does NOT account for rows 2 and 4, and this file does not offer it as an
  excuse for them: the cause of those two was established separately, by a
  third build, and is summarised under the diagnostic section below.

EVIDENCE, NOT EXIT CODES
+++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++
  NO VERDICT IN THIS FILE RESTS ON A PROCESS EXIT STATUS.  Every row above
  rests on a digest of a produced artifact.

  This is mandatory rather than stylistic, and the reason is a repository fact
  rather than a preference.  Re-verified for this record with
  sed -n '143,144p' Gruntfile.js:

    L143   a comment stating the intent, that the default is made forcing so
           as not to break the project
    L144   grunt.option('force', true)

  Forced execution MASKS TASK FAILURES and lets a broken build exit zero.  It
  did exactly that during the captures on both sides, which is the point: the
  baseline build exited ZERO while printing a missing-module warning and a
  continued-under-force notice, and the migrated build likewise exits zero while
  its last task fails.  An exit-code-based gate would have called both healthy.

  WHAT WAS CONFIRMED BEFORE DIGESTING, PER ARTIFACT.  All five were confirmed
  PRESENT and NON-EMPTY, and each row above carries its byte size: 4264064,
  2011927/2011925, 3986503, 388637/389426 and 126072.  None is zero, none is
  implausibly small for what it is, and the digest gate recorded 5 of 5
  required digests produced with 0 failures on each side - a missing file, an
  empty digest, a malformed digest, an unavailable digest tool or a record
  labelled with anything other than its own key would each have been a gate
  FAILURE and none would ever have been recorded as a row of evidence.

  THE VENDOR BUNDLE, specifically.  A concatenation whose source list resolved

  writes its sources IN LIST ORDER - see the asset-layout section below for why

  it carries 0, which is correct for this branch - but that the cache-busting
  task ran and produced the hashed companions listed above, and that the page
  itself is byte-identical at 126072 bytes on both sides.  The link from the
  page to the five digests on this branch is the digest rows themselves

A DIAGNOSTIC AID, CORRECTLY FRAMED
+++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++
  Offered as a diagnostic only.  It is NOT a substitute for comparing all five
  rows independently, and the five rows above were each compared on their own.

  Because the cache-busting task hashes the distribution directory AFTER the
  four bundle tasks have written it, home.html's bytes depend on the final
