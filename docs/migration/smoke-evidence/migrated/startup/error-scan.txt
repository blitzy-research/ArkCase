- why this file is .txt and not .log.  The seven .log files here are excerpted log
  regions -- what the application emitted.  This file is the outcome of running a scan
  over them -- what the scan concluded.  Those are different kinds of artefact, and a
  .log extension would present this one as an eighth region, blurring the two and
  weakening the evidence chain.  .txt is the honest extension and is sanctioned for
  this folder alongside .log; it is also established vocabulary here rather than an
  exception, since it is already the extension of scores of derived records across this
  evidence tree, and the sibling capture script writes its own per-flow verdicts as
  .result.txt records of exactly that kind.

  this scan examines originates in the container's own log directory, a directory
  literally named logs, while the archive directory here is startup/.  That is not a
  stylistic choice: the repository ignore file matches bare, leading-slash-free tokens
  at ANY depth, and logs is one of them, so a subdirectory named logs beneath this path
  would be silently uncommitted -- every local check would pass while the committed
  deliverable was empty.  Re-verified at this exact depth before this file was written:
  a .log placed under a logs/ directory here is ignored, and so is one placed under bin/

  none of the six ignored bare names -- target, bin, partition-descriptor,
